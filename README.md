# niri-recorder

Local-first screen recorder for Wayland/Niri on Fedora. Captures a full
output or a selected region to MP4/H.264 using `wf-recorder` — no audio,
no network, no portal prompts.

**Status: GUI + optional daemon (Phase 6).** A bare `niri-recorder`
launches the GTK4/libadwaita window; every feature is also available
from the command line below. See `docs/ROADMAP.md` for phase status.

## Supported environment

| Requirement | Status |
|---|---|
| Fedora 44, native Wayland session | Verified on target |
| Niri compositor (dual output DP-3 + eDP-1, 1920×1080@60) | Verified on target |
| Intel CometLake-H UHD (iHD) | Verified; software encode only |
| Multi-monitor | Verified (`--output` on DP-3 + eDP-1, per-display capture) |
| Other compositors | Untested; do not assume Sway/Hyprland results apply |

See `docs/WAYLAND-NIRI-COMPATIBILITY.md` for the full verified/pending
matrix and `docs/CAPTURE-BACKENDS.md` for why `wf-recorder` was chosen
over `wl-screenrec` and the XDG portal.

## Features

- Record one full display (`--target display`, `--output NAME`)
- Record a screen region via `slurp` (`--target region`)
- Graceful stop: `niri-recorder stop` or Ctrl-C → SIGINT → finalized MP4
- Single-instance guard via a user-private pidfile
- Collision-safe filenames; in-progress files staged as `.part`
- `status` and `diagnostics` commands
- Optional configurable countdown before capture (0/3/5/10 s, cancellable)
- In-window start/stop shortcuts (`<Control>r` / `<Control>s` by default)
- Thumbnails in the recent-recordings list (cached, generated by `ffmpeg`)
- Opt-in retention (max file count / max age), off by default
- Encoder presets: software default, hardware preference with fallback
- Optional `niri-recorder daemon` for CLI control that survives workspace
  and focus changes; `start`/`stop`/`status` use it automatically
- DankMaterialShell bar widget/Control Center tile in `data/dms-plugin/`
- Desktop notifications on start, stop/saved, and failures (`notify-send`, enabled by default)
- No audio capture, ever — the backend never passes an audio flag

Known limitations: variable frame rate output (wlr-screencopy damage
tracking); cursor visibility cannot be controlled (wf-recorder 0.6.0 has
no cursor flag); hardware encoders are probe-selected but **not verified**
to encode successfully on this CometLake iHD machine, so `encoder =
"auto"` stays on software; `--output NAME` is not validated against
detected outputs (a bad name surfaces later as a wf-recorder exit —
`capture ended early` / `stop failed`, exit 3); slurp region geometry
across two outputs unverified; the DMS plugin loads in a live DMS 1.6
session but bar rendering/click behavior is still a manual check.

## Install dependencies (Fedora 44, verified package names)

```sh
sudo dnf install wf-recorder slurp ffmpeg
```

`ffmpeg` supplies `ffprobe`, used by `diagnostics` and for checking
recordings. `niri` itself must be installed and running — output
enumeration uses `niri msg --json outputs`.

## Usage

### GUI

Run `niri-recorder` with no arguments (or launch **Niri Recorder** from
your app launcher) to open the window: pick display or region, set
fps/quality, start/stop, and act on finished recordings. Settings are
shared with the CLI via the config file below.

### CLI

```text
niri-recorder start                          # record sole/first display (foreground, notifies)
niri-recorder start --target display --output DP-3
niri-recorder start --target region          # slurp region picker
niri-recorder start --no-notify              # suppress desktop notifications
niri-recorder stop                           # stop the recorder (daemon or pidfile)
niri-recorder stop --no-notify               # stop without notification
niri-recorder status                         # "recording pid=N" or "idle"
niri-recorder diagnostics                    # tool versions, outputs, backend caps
niri-recorder daemon                         # foreground control daemon (optional)
```

Without a daemon, `start` runs in the foreground of its own process.
When `niri-recorder daemon` is running, `start` forwards the request and
returns immediately; `stop` returns once the file is finalized. See
`docs/DAEMON.md` (including the systemd user unit in
`data/niri-recorder-daemon.service`).

### In-window shortcuts

The GUI binds `Ctrl+R` (start) and `Ctrl+S` (stop/cancel countdown) while
its window is focused. Rebind or disable them with `start_shortcut` /
`stop_shortcut` in `config.toml` (GTK syntax, e.g. `<Super>r`; empty
disables). Wayland has no portable app-level global hotkey — use a niri
bind for a shortcut that works anywhere.

### Niri keybindings

Bind start/stop in `~/.config/niri/config.kdl`, inside the `binds {}`
block (`spawn` takes the command and its arguments):

```kdl
Mod+Shift+R { spawn "niri-recorder" "start" "--target" "display"; }
Mod+Shift+S { spawn "niri-recorder" "stop"; }
```

If `Mod+Shift+R` is already bound (niri defaults use it for
`switch-preset-column-width-back`), pick a free key or rebind the
default — two binds cannot share the same key.

Exit codes: `0` ok (incl. `status` and cancelled region select),
`1` not recording / already recording / cannot signal, `2` backend
missing or CLI parse error, `3` capture failure.

## Configuration and output

Config: `~/.config/niri-recorder/config.toml` (all keys optional):

```toml
output_directory = "~/Videos/Screen Recordings"
default_target = "display"    # display | region
default_fps = 30              # 24 | 30 | 60 only
quality = "standard"          # standard | high
preferred_backend = "auto"    # only wf-recorder exists; auto resolves to it
encoder = "auto"              # auto | software | hardware | ffmpeg encoder name
countdown_seconds = 0         # 0 | 3 | 5 | 10 (GUI only)
start_shortcut = "<Control>r" # empty disables
stop_shortcut = "<Control>s"  # empty disables
cleanup_enabled = false       # opt-in retention, off by default
cleanup_max_files = 20        # 0 = no count limit
cleanup_max_age_days = 30     # 0 = no age limit
notifications = true          # desktop notifications on start/stop/save
# last_output is written automatically when a display is recorded.
```

`encoder = "hardware"` picks the first hardware H.264 encoder listed
by `ffmpeg -encoders` and falls back to software when none is listed.
Listing is not proof of working hardware encoding — this machine has not
verified it, and a listed encoder that fails at start is reported rather
than retried. Only H.264 encoders are offered because output is MP4.
Cleanup
only ever deletes finished `screen-recording-*.(mp4|webm)` files, never
`.part` files or other files in the directory.

Output: `screen-recording-YYYY-MM-DD_HH-MM-SS.mp4` in the output
directory (`-1`…`-99` appended on collision). In-progress captures are
written as `<name>.mp4.part` and renamed once the recorder has exited and
the file is non-empty; a non-zero exit keeps the file but is reported as
a failure instead of a clean save.

Runtime state: `$XDG_RUNTIME_DIR/niri-recorder/recorder.pid` and, while
the daemon runs, `control.sock` (both mode 0600 in a 0700 dir; falls back
to `/tmp/niri-recorder-<uid>` without a runtime dir).

Thumbnails are cached under `$XDG_CACHE_HOME/niri-recorder/thumbnails/`
and are derived from the recordings; deleting that directory is safe.

## Troubleshooting

Run `niri-recorder diagnostics` first — it reports niri, wf-recorder,
slurp and ffprobe presence, detected outputs, and backend capabilities.
Error-by-error guidance is in `docs/TROUBLESHOOTING.md`.

## Security and privacy

- Recording is fully local; no telemetry, accounts, or upload paths.
- Screen recordings capture whatever is on screen — including private
  notifications, passwords managers, and documents. Treat output files
  accordingly.
- The pidfile and (optional) daemon socket live in a user-private
  runtime dir (0600 files in a 0700 dir). The socket is local-only, has
  no network listener, and requires no root.
- No audio is captured; nothing requests microphone access.

## Project layout

`src/ui` (GTK4/libadwaita window — bare `niri-recorder`) → `src/cli`
(clap front-end) → `src/app` (`Recorder` controller, state
machine, pidfile) → `src/capture` (`CaptureBackend` trait, `wf-recorder`
backend, encoder probing, managed subprocess) → `src/files` (output
naming/finalization, retention), `src/config` (settings).
`src/daemon` serves the same `Recorder` over a local Unix socket. Full
picture in `DESIGN.md`.
